# Техническое задание: доведение «Собачьего дворика» до стабильной играбельности

## 1. Цель

Довести статическую HTML5-игру до состояния, в котором основной игровой цикл, локальное и облачное сохранение, рекламные и платёжные интеграции, безопасность клиентского рендера, тестируемость и загрузка работают предсказуемо на десктопе и мобильных устройствах.

## 2. Ограничения и исходные условия

Проект остаётся статическим HTML5-проектом без обязательного сборщика. Игровая механика и формат сохранения v5 должны сохранять обратную совместимость. Реальный GamePush `projectId`, `publicToken` и модель player не должны угадываться или заменяться тестовыми значениями. До получения актуального Install Code интеграция должна корректно переходить в локальный режим и показывать диагностический статус.

## 3. Этапы работ

| Этап | Результат | Критерий готовности |
|---|---|---|
| A. Диагностика GamePush | Проверены project ID, public token и поле `save` | SDK не выдаёт 400 ошибок; cloud save, ads и payments имеют отдельные статусы |
| B. Надёжное сохранение | Последовательная очередь сохранений | Одновременные вызовы не перезаписывают более новое состояние старым payload |
| C. Безопасный DOM | Сохранённые строки не интерпретируются как HTML | Квесты и сюжет используют экранирование или `textContent` |
| D. Тесты | Тесты миграции, сериализации и экономики | Тесты запускаются одной командой и проверяют граничные значения |
| E. Модули | Чистая игровая математика вынесена из UI | Экономику и save-модель можно тестировать без браузера |
| F. Ассеты | Современные форматы и уменьшенные изображения | Поддерживается WebP/AVIF с fallback; начальная загрузка уменьшена |
| G. Диагностика UI | Отдельный статус SDK, cloud save, ads и payments | Пользователь видит локальный режим и причину fallback |
| H. Регрессия | Полный smoke-тест и публикация | JS/CSS/HTML проверки, браузерный smoke-тест, чистый diff и push |

## 4. Порядок реализации

Сначала выполняются этапы B, C и G, потому что они исправляют потерю прогресса, XSS и неясное состояние интеграции. Затем выполняются D и E для защиты от регрессий. Оптимизация ассетов выполняется после проверки ссылок и fallback. Этап A завершается после передачи актуального Install Code из панели GamePush.

## 5. Критерии 100% завершения

Проект считается завершённым, если выполняются следующие условия:

1. Игрок может начать игру, кликать, покупать улучшения, запускать прогулки и события.
2. Локальный сейв сохраняется и мигрирует без потери прогресса.
3. Облачное сохранение сериализуется последовательно и сообщает об ошибках.
4. Данные из сейва не создают HTML или JavaScript в DOM.
5. Тесты проверяют миграции, стоимость улучшений, softcap, офлайн-награду и граничные значения.
6. GamePush подключается с актуальными данными панели либо игра прозрачно работает в локальном fallback.
7. Статус интеграции различает SDK, cloud save, ads и payments.
8. Изображения имеют оптимизированный формат с fallback.
9. Нет ошибок синтаксиса, ссылок на отсутствующие DOM-элементы и ошибок в консоли при локальном запуске.
10. Изменения опубликованы в `main` после проверки.

## 6. Неперекрываемые блокеры

Нельзя завершить этап A без актуального Install Code GamePush. Нельзя считать payments и cloud save рабочими только по наличию объекта SDK. Если GamePush недоступен, локальный режим должен оставаться полностью играбельным.

## 7. План проверки

После каждого этапа выполняются синтаксическая проверка JavaScript, `git diff --check`, локальный HTTP smoke-тест и browser smoke-тест. Перед публикацией дополнительно выполняются все тесты и проверяется, что `HEAD` совпадает с `origin/main`.

## 8. Будущая модульная граница

UI и обработчики остаются в `game.js` на первом проходе. Чистые функции состояния, миграции и экономики выносятся в отдельный `js/game-core.js`, который не зависит от `window` и DOM. Дальнейшее разделение событий, прогулок и рендера выполняется только после стабилизации API core-модуля.

## 9. Приёмка

Приёмка проводится по реальному браузерному сценарию: новый игрок, клик, покупка, расход энергии, прогулка, событие, сохранение, перезагрузка, восстановление сейва, повреждённая строка квеста и недоступный GamePush. Любой сценарий с потерей прогресса или выполнением HTML из сохранения считается незавершённым.
